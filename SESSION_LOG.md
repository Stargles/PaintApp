Session 22 — 2026-07-22: changed: Fixed fill-tool undo/redo, which was broken in several ways. Bugs found (via new failing UI tests, then fixed): (1) a just-applied but still-adjustable fill wasn't on the undo stack at all — canUndo stayed false on a blank canvas, and tapping Undo elsewhere silently reverted the *previous* action while the fill lingered onscreen; (2) two-finger-tap-to-undo both discarded the in-flight fill (cancelInteractiveFill) AND called undo(), doing two actions on one gesture; (3) registerUndoableCelChange's registered undo closure never re-registered a matching redo, so a second undo→redo cycle silently did nothing (affected fill/select/move/duplicate alike); (4) commitInteractiveFill used whatever undo manager was "active" at commit time rather than the one captured when the fill began, so a fill finalized after the active layer/cel changed could land on the wrong stack. Fixes: CanvasManager.undo()/redo() now call a new finalizeFillForHistoryAction() first (commits a lifted adjustable fill, or drops one still under the finger) so undo/redo always acts on settled state; refreshUndoRedoState() reports canUndo=true while a fill is pending even with an empty stack; registerUndoableCelChange gained an optional explicit undoManager param (used by the fill's commit) and now recurses via a new registerCelReversal so undo/redo cycles indefinitely; two/three-finger taps now just call undo()/redo() (no separate cancelInteractiveFill); handleActiveContextChanged commits a pending fill before the context switches; new StrokeCanvasView.onStrokeBegan hook commits a pending fill *before* a new stroke's own undo registers, so drawing over a fill undoes in the intuitive order (stroke first, then fill) instead of the fill sneaking out from under the stroke. Added accessibility identifiers toolbar.undoButton/redoButton/brushButton (previously untestable). New UI tests: testUndoRemovesFillKeepingUnderlyingStrokes, testRedoRestoresUndoneFill, testUndoEnabledAndClearsFillOnBlankCanvas, testFillUndoRedoCyclesRepeatedly, testDrawingOverFillCommitsFillAndStrokeUndoesFirst — all reproduced their bug against the pre-fix code (verified failing first) and pass after the fix.
