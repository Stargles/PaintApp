Session 22 — 2026-08-10: LAYER_COMPOSITING.md Phase 0. (0a) VectorCanvas.render() early-outs on an empty display list to a shared 1x1 transparent image and memoizes nothing, so an empty vector layer no longer retains a canvas-sized sheet (16.8 MB at 2048²) the moment StrokeCanvasView's didSet renders it; renderIfNonEmpty() lets the display path set imageView.image = nil. The guard is on _elements.isEmpty alone, not on transform identity — an affine of nothing is still nothing, and resized(to:offset:) leaves empty canvases translated. Ten XCUITests assumed raster; those about layer *content* now read the vector marker, those about the raster tier itself (Move's floating-piece lift, select-then-fill, the shape bake) ask for a raster layer via the new addRasterLayer helper. Layer names from the default + are now "Vector N" — a user-visible change worth a product call. Full run green.

Session 24 — 2026-08-11: LAYER_COMPOSITING.md phases 2 and 3 (less the sandwich). RenderRequest is §9.1's immutable snapshot — tree, per-leaf CGImages resolved on a @MainActor builder modelled on ProjectStore.SaveSnapshot, frame, canvas size, background, quality; Compositor picks a CoreGraphics reference or a Metal backend behind a flag defaulting to CPU. Two decisions made the byte-identical gate reachable: a transparent group gets no buffer of its own (an intermediate re-quantizes to 8-bit once per nesting level, which would fail any document containing folders), and a group's own isVisible is not consulted, because toggleFolderVisibility still writes through to descendants and honouring it would change shipped behaviour that phase 1 pinned. The gate holds literally — max channel delta GPU vs CPU is 0, not the ±1 that float32-vs-8-bit rounding predicted. The GPU became testable in the fast tier for the first time, which took Composite.metal being an explicit member of PaintSoftwareUITests *and* asking for the library by Bundle(for:) rather than Bundle.main, since under XCUITest the main bundle is the runner app and not the .xctest plug-in the metallib is built into; MetalFillEngine does neither, so its GPU path is still XCUITest-only. Phase 3 routed the thumbnail through Compositor and deleted PixelOps.compositeCanvas, whose flat walk now lives in CompositorParityLogicTests as the frozen oracle. The rest of §5.2's convergence list was smaller than written: export does not exist, mergeLayers flattens two cels below the compositor, and the onion skin flattens a cel set at alpha 1 ignoring layer opacity/visibility, so converging it is a product decision — all three recorded in the doc. PerfBaselineTests gained compositor cases: six layers at 2048² cost snapshot 276 ms vs CPU composite 84 ms, nesting six levels deep is free (38.6 vs 38.9 ms), and the GPU's 1189 ms is simulator-bound. Those numbers killed the texture upload cache, which was measured never hitting — PixelOps.rasterize mints a fresh CGImage per call, so an identity key cannot hit — and with it LayerRenderSource.contentVersion, to be reintroduced with the cache that can use it. Full run 732/0/1 on an erased simulator, the skip being the FillUITests XCTSkip already in BUGS.md. §5.2's sandwich is deliberately not built and moved to phase 5 by the product owner: nothing consumes it until a layer has a blend mode, it rewrites the most latency-critical code in the app, and the measurement says it would cache the cheaper half. CLAUDE.md gained the false-green trap: xcodebuild prints TEST SUCCEEDED and exits 0 having run nothing when -only-testing is malformed, which zsh causes by not word-splitting unquoted $VAR.
