Session 51 — 2026-08-20: Closed `tmp/text3` — **Add Text stage 3**, ADD_TEXT.md §3's *"vector layers keep it editable"*. On a raster layer text still bakes; on a vector layer the session now lands a `VectorTextElement` in the cel's display list, saves as itself, reloads as itself, and **re-opens under a tap** — `beginTextSession` asks `topmostText(atCanvasPoint:)` before it places anything, loads the element's own recipe and frame into the draft tier, and `commitInteractiveText` upserts it back **at its own index**. Deleting `Tool.textUnavailableReason`'s `.vector` arm was the whole of the UI change, which is exactly the un-shipping stage 1 planned for. **Four calls worth knowing.** *(1)* `Kind.text` is numbered **below** `.stroke` and a new object is `append`ed rather than inserted: the rawValue governs insertion arithmetic, not z-order, and keeping `.stroke` highest is what makes a brush stroke drawn after an erase still land at the end of the list, above the `.erase` punch `eraseHybrid` *appends*. Number text above strokes and that stroke is inserted **underneath a punch that predates it** and gets eaten by an erase that happened before it existed — the failure is invisible until someone erases, then types, then draws. Text and strokes therefore stack chronologically, and §1's "an erase stroke above a text element already masks it" holds unchanged. *(2)* Undo swaps the **whole `elements` array**, not the `texts` bucket, unlike `registerVectorFillUndo` it is otherwise a copy of: the kind-filtered setters gather their kind back at the first one's index, which is order-stable for a contiguous bucket and not for text, which is interleaved with strokes by construction. *(3)* `TextLayout.draw` went from `private` to internal so the vector flatten reaches the **same rasterizer** the bake and the live overlay use — stage 1's report says the overlay's `UITextView` draws no glyphs for precisely this reason, and a second rasterizer on the vector path is the divergence §2 warns about; `TextMeasure.inkBounds` (measure-only, no context, no image) went beside it rather than into a file of its own, since it is called from inside `VectorCanvas`'s non-reentrant lock on the eraser's garbage-collection path. *(4)* **`isTextEditLive` latches forward, not backward** — the one place the sketch in §4 rule 5 would have been wrong if followed literally. `isSandwichStrokeLive` holds the *previous* pass's content version because a dab publishes nothing; opening a text edit does the opposite (it sets `editingElementID`, which invalidates), so freezing against the previous pass would composite the committed glyphs **underneath the live editor** and the artist would see their text twice.
