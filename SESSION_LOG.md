The Metal backend stopped declining groups that need their own buffer, which phase 4 could survive only while a faded group was the sole trigger. PixelOps.rasterize is memoized on model state — §5.2 names it as the fix for the measured 276 ms snapshot and the sandwich structurally needs it — keyed on cel id, object identity *and* version for both tiers, because a cel id outlives the buffers under it: reopening a project rebuilds every RasterLayerTexture with its counter back at 0 under the same id, so a version-only key would serve pre-edit pixels. **Phase 5 is half done: the compositor blends and the thumbnail proves it, but reconcileLayers still hands Core Animation flat siblings, so a Multiply layer looks normal on the live canvas.** That is §5.2's sandwich and it is all that stands between this feature and being usable.
