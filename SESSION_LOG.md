Session 33 — 2026-08-16: **The compositor was never GPU-based on the owner's device.** `Compositor.backend` has defaulted to `.coreGraphics` since phase 2 and nothing in the app has ever written it — only test bodies — so `MetalCompositor`, `Composite.metal`, `EffectPipelines` and `MetalEffects` were fully written, parity-tested and unreachable in the shipped binary. Flipping it naively would have been *slower*, and the reason is the finding: **a repaint is three composites** (`full`/`below`/`above` over one shared `sources` array) and `upload` had no cache, so the GPU moved ~100 MB three times per rebuild. The first upload cache keyed on the rendered `CGImage` and was measured at a zero hit rate; the key that works is `LayerContentVersion`, which the request has carried since phase 6 and which `LayerRenderSource`'s comment already named — **plus the pixel dimensions**, since a content version does not move when the *canvas* resizes and a wrong-sized texture under a full-canvas dispatch is a garbage frame, not a stale one. `ScratchTexturePool` also went cross-composite: its comment had deferred that pending "the consumer that would [answer the eviction rule] is §5.2's sandwich", and the sandwich made the rule *smaller* — occupancy is bounded by nesting depth, so the only lifetime question is the canvas size. Warm sandwich rebuild 491.8 → 31.3 ms; a one-pass effect 247.3 → 18.8 ms against CoreGraphics' 7047.5 ms, because a grade on the CPU walks 4.2M pixels in Swift and on the GPU is one more dispatch over a resident texture. Default flipped to `.metal`, CoreGraphics kept as oracle and fallback. **Step 4's dirty-rect scissoring was deliberately not built, on evidence**: decomposing a warm composite by layer count gives CoreGraphics a ~8 ms/layer slope with no floor and Metal an ~11.4 ms *floor* with a slope at the noise — so 69–86% of a GPU frame is the command-buffer round-trip and the 16.8 MB readback, which no scissor touches. The next real win is compositing into a displayable surface instead of reading back. Also: a **render resolution** picker in Actions (Full/75%/50%, persisted, reaching only `makeSandwichRequests` so exports and thumbnails are untouched, and only engaging where `needsCompositorOnCanvas` does), and two test-hygiene traps that bite silently — a persisted preference set by a test leaks through `UserDefaults` into later tests *and the next run on the same simulator*, and four suites restored the literal `.coreGraphics` in `tearDown`, which was a correct restore only while that was the default (hence `Compositor.defaultBackend`). Fast tier 949 tests, 945 pass, 1 inherited failure (`EffectLayerLogicTests.testAnEffectLayerCarriesNoBlendModeButStillClipsToBelow`, now in BUGS.md).
